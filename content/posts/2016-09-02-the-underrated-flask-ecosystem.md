I've been building Flask apps for years. Flask is great. There are not many web frameworks that can compare to its simplicity and unopinionated-ness. With about five lines of code you can be up and running. Especially with the fronted-heavy style of today, there might not be need for much more than that!

Of course in a real-world application, the backend needs to be more substantive. At a minimum it needs to connect to a database, expose a number of endpoints, and provide authentication/authorization mechanisms. The cool thing here is that Flask has a great extension model with bulletproof libraries that provide this functionality for us, for free. Let's talk about the wonderful Flask ecosystem.

**Flask-Login**

Flask-Login could be the only authentication library that I have enjoyed using. In my experience, authentication libraries commonly are black-box setups that require excessive amounts of studying documentation before even a basic implementation can be working properly. Flask-Login is the opposite. It has a small, intuitive API with the perfect amount of customizability. The documentation is straightforward and you can go from `pip install flask-login` to a working authentication scheme in under an hour.

Using Flask-Login is as simple as adding function decorators where needed and ensuring your User class has the attributes required by the API. Once that is done your app is ready to call `login()` and `logout()` and be done with authentication frustrations. 

**Flask-SQLAlchemy**

The SQLAlchemy library is incredibly powerful. It provides features for nearly every database interaction imaginable. The thing with SQLAlchemy though is that its main pro is that it's a beast, and its main con is that it's a beast. While you can handle every common and uncommon scenario with SQLAlchemy, there is a seemingly endless API to navigate.

This is why Flask-SQLAlchemy is so invaluable. It solved that problem by providing a massive set of sensible wrappers and sane configuration defaults. By using this extension you now only need to work with the small portion of the SQLAlchemy API that doesn't have Flask-SQLAlchemy defaults.

**Flask-Restless**

Autogenerated REST APIs are an immensely valuable asset to backend environments. These have been done with tools like Loopback and Django Rest Framework, and are now available to us in Flask. Flask-Restless takes your SQLAlchemy models and, with a few lines of code, provides a plug-n-play REST API for your app. Truly amazing stuff. And, needless to say, it is configurable all the way down such that you can preprocess and postprocess every HTTP request as needed. This is especially handy because you can add middleware functions that can be used to tie your Flask-Login workflow into the Flask-Restless logic!

**Conclusion**

I touched on just my top three Flask extensions. Authentication, ORM code, and REST API handlers are necessary components of most webapps in 2016. The above extensions provide a fun, reliable, and headache-free working environment for developers writing server-side logic in Python. 

This post was intended to cover the most essential Flask libraries for your backend. My next post on this topic will cover even more extensions, ones that add very nice-to-have features like admin interfaces and easier interfacing with MongoDB.
